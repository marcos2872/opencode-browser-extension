15. Limits and privacy

  • Everything is local: the extension talks to 127.0.0.1; the plugin listens only on loopback (ports 8799–8802) and requires a “hello” from the extension before serving.
  • The panel is a single view: two open windows show the same conversation.
  • The conversation↔group bond does not survive closing Chrome completely.
  • Up to 4 conversations with detailed state in memory at the same time.
  • One streaming reply at a time, but several conversations can run in parallel.
  • Automatic group creates one blank tab per conversation; groups of conversations deleted outside the extension are only released on the next browser start.
  • The permission card is modal: while a request is open, the panel is covered — answer it (or use Esc) to continue.

16. Quick reference

Paths

WhatWhere
Extension builddist/ (it is the folder to load in Chrome)
Plugin and agent~/.config/opencode/plugins/
Browser conversations~/.opencode-browser-extensions
Agent screenshots~/.cache/opencode-browser/capturas/
Relay token and port$XDG_RUNTIME_DIR/opencode-browser/relay.json or ~/.cache/opencode-browser/relay.json

Useful commands

npm run build              # generates dist/
npm run install:plugin     # copies plugin and agent
opencode service restart   # reloads plugin and agent
opencode pair              # generates the pairing link
curl http://127.0.0.1:8799/health

Requests that work well

  • “Open example.com and tell me the page title.”
  • “Read the current page and list the menu links.”
  • “Fill in the contact form with test data and show me a screenshot before submitting.”
  • “Investigate why the Save button does not respond: check the console and the network.”
  • “Look up the price of this product in three stores and put it in a table.”
  • “Record a GIF showing the login step by step.”
