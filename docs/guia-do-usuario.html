Guia do usuário — OpenCode Browser

Este guia percorre todas as funcionalidades da extensão, na ordem em que você vai encontrar cada uma: instalar, conectar, conversar, deixar o agente mexer no navegador, aprovar permissões, rodar várias conversas ao mesmo tempo e ajustar as configurações.

O OpenCode Browser é um painel lateral do Chrome que conversa com o OpenCode Terminal rodando na sua máquina. O agente lê páginas, clica, preenche formulários e navega dentro de um grupo de abas isolado por conversa — e cada ação que muda algo pede a sua permissão (ou não, conforme o modo escolhido).

Nada sai do seu computador: a extensão fala com 127.0.0.1, e o plugin que dá as ferramentas ao agente só escuta em loopback.

ItemVersão mínimaObservação

Os modelos são os mesmos que você já usa no OpenCode: se o seu OpenCode funciona no terminal, a extensão funciona.

2. Instalar a extensão

2.1 Pelo script (recomendado)

Na pasta do projeto:

./scripts/install.sh        # Linux e macOS
.\scripts\install.ps1       # Windows (PowerShell 5.1+)

O script, nesta ordem:

  1. confere se existem Node.js 20+, npm e OpenCode v2+ (para com uma mensagem clara se faltar algum);
  2. instala as dependências (npm install);
  3. gera o build da extensão (npm run build) em dist/;
  4. copia o plugin e o template do agente para a pasta de plugins do OpenCode (npm run install:plugin);
  5. reinicia o serviço do OpenCode (opencode service restart);
  6. espera o plugin responder em http://127.0.0.1:8799/health.

Se o passo 6 falhar, o próprio script avisa: abra o painel da extensão e verifique.

O install.sh reinicia o serviço do OpenCode. Se você estiver usando o OpenCode em um terminal, a sessão atual cai por alguns segundos e reconecta — não é erro.

2.2 Manual

npm install
npm run build
npm run install:plugin
opencode service restart

Depois, no Chrome:

  1. abra chrome://extensions;
  2. ligue o modo desenvolvedor (canto superior direito);
  3. clique em Carregar sem compactação e escolha a pasta dist/ do projeto (não a raiz);
  4. o ícone do OpenCode Browser aparece na barra.

2.3 Depois de atualizar o código

O Chrome mantém o service worker em cache. Sempre que você rodar npm run build de novo:

  1. abra chrome://extensions;
  2. clique em Recarregar no cartão da extensão.

Sem esse passo, o comportamento antigo continua no ar mesmo com o código novo.

3. Conectar a extensão ao OpenCode (pareamento)

  1. Abra o painel: clique no ícone da extensão, ou use o atalho Ctrl+Shift+O (Command+Shift+O no macOS).
  2. Na primeira vez aparece a tela “Conecte o navegador ao OpenCode da sua máquina”.
  3. No terminal, rode:

bash opencode pair

  1. Copie o link exibido (é o mesmo que abre a interface web do OpenCode) e cole no campo “Link do opencode pair”.
  2. Clique em “Conectar ao OpenCode”. Ao terminar aparece o aviso “Conectado ao OpenCode.”

O link é de uso único e expira em 5 minutos. Se expirar, rode opencode pair de novo. O token anterior continua válido até você desconectar.

Se o pareamento falhar

MensagemO que fazer

“O link precisa começar com http:// ou https://.”Você colou só o código; cole a URL completa
“O link não contém /auth/connect/<código>.”Não é um link de pareamento
“Não foi possível falar com o OpenCode em … Ele está rodando?”O servidor não está no ar: rode opencode serve

4. Instalar o plugin de ferramentas

O chat funciona só com a API — para o agente controlar o Chrome, ele precisa do plugin:

npm run install:plugin
opencode service restart

O comando copia, para a pasta de plugins do OpenCode:

  • browser-relay.ts — o servidor que expõe as ferramentas do navegador;
  • opencode-browser.agent.md — o template do agente opencode-browser.

e cria a pasta padrão das conversas do navegador (~/.opencode-browser-extensions).

Confira se está tudo certo:

curl http://127.0.0.1:8799/health

No painel, o rodapé do composer mostra “ferramentas conectadas” quando o plugin está ativo.

Se o plugin não conectar

“Plugin recusou a conexão — confira o ID da extensão”A extensão não é a esperadaRecarregue a extensão ou ajuste OPENCODE_BROWSER_EXTENSION_ID

Mantenha uma única cópia do plugin na pasta de plugins. Duas cópias registram o mesmo plugin e uma delas falha.

6. Sua primeira conversa

  1. Digite no campo “Peça algo ao OpenCode...” e pressione Enter.
  2. A resposta aparece em streaming; enquanto o agente trabalha, o campo mostra “O agente está trabalhando...”.
  3. Quando ele usa uma ferramenta, surgem os cards (veja a seção 7).
  4. Se ele precisar de permissão, o card aparece sobre o painel (seção 10).

A tela vazia traz quatro sugestões prontas:

  • “Abra o Hacker News e resuma as 5 principais notícias de hoje.”
  • “Leia a página atual, encontre o formulário de contato e preencha com dados de teste.”
  • “Investigue os erros do console e as requisições de rede desta página.”
  • “Pesquise o preço de um produto em três lojas e compare em uma tabela.”

Comandos com barra

Digite / (sem espaço depois) para abrir o menu de comandos. A lista vem do seu OpenCode e mostra até 6 sugestões; escolher uma completa o campo com /nome . Depois de escolher, escreva o resto e envie — por exemplo /review corrija o diff.

Se você enviar /nome e mais nada, o comando roda sem argumentos.

Rascunho por conversa

O texto que você digitou fica guardado por conversa. Trocar de conversa e voltar não apaga o que estava escrito. Se você digitar antes de existir conversa nenhuma, o texto acompanha a conversa que for criada.

Contexto e custo

O rodapé do composer mostra, quando disponível:

  • “Contexto 1.234 (12%)” — tokens da última requisição e quanto isso ocupa da janela do modelo;
  • “Sessão US$ 0,0000” — custo informado pelo OpenCode.

Sem esses dados, o rodapé mostra a dica “Enter envia · Shift+Enter quebra linha”.

Parar uma execução

Com o botão Parar no composer você interrompe a conversa exibida. Cada conversa tem seu próprio botão: parar uma não afeta as outras.

Cards de ferramenta

Cada chamada aparece no chat com um rótulo em português — “Navegar”, “Ler página”, “Clicar na página”, “Preencher campo”, “Console”, “Rede” — e um status: ok, erro ou rodando.

Você escolhe quanto detalhe quer ver em Configurações → Ferramentas no chat:

ModoComo fica
Agrupadas (abrem em um modal) (padrão)Uma linha-resumo por execução (“4 ferramentas · ver”); o detalhe abre no modal “Ferramentas desta execução”
Linhas compactas, uma por chamadaUma linha por ferramenta, com o erro resumido na própria linha
Cards completos, com parâmetros e resultadoTudo aberto no chat, incluindo o JSON de entrada e a saída
Ocultar tools e raciocínio (só “trabalhando”)O chat mostra só a atividade (“trabalhando: lendo a página”)

No modo agrupado, o modal tem filtro “Somente erros” e fecha com Esc ou clicando fora.

Screenshots aparecem como imagem dentro do card (até 3 por vez) e também são salvas em disco: o caminho do arquivo vem na resposta do agente.

8. Abas e grupos: onde o agente trabalha

Cada conversa tem o seu grupo de abas, com título “OpenCode · nome da conversa” e uma cor própria. É o espaço de trabalho daquele agente — ele não mexe nas suas outras abas.

Abas em segundo plano

Por padrão a extensão não rouba o foco: abas criadas ou anexadas pelo agente nascem em segundo plano, e a janela em que você está trabalhando continua onde está. Se você preferir ver as abas surgindo, ligue “Permitir que abas abertas ou anexadas pelo agente venham para frente” nas configurações.

Na página em que o agente está agindo aparece uma moldura laranja com o aviso “OpenCode está nesta aba”, um Parar e um cursor animado mostrando onde ele clica.

Conectar uma aba sua ao agente

  • Conectar aba atual (ícone de link na barra de conversas): traz a aba ativa para o grupo da conversa.
  • Com abas conectadas, o mesmo botão abre a lista: “Conectar nova aba” e, em cada aba, “Remover … do contexto”.

Remover uma aba do contexto não fecha a aba: apenas a tira do grupo, e ela volta a ser uma aba normal sua.

Abas de outra janela não podem ser anexadas. A extensão responde: “A aba está em outra janela. Abra uma aba nova pela sessão ou mova a aba para a janela do grupo antes de anexá-la.”

O grupo nasce quando é preciso

Se a opção de criar grupo ao iniciar conversa estiver desligada (padrão), o grupo aparece no primeiro uso do navegador pelo agente — ou quando você conecta uma aba. É o fluxo mais econômico: nenhuma aba em branco acumulada.

9. Várias conversas ao mesmo tempo

Este é o ponto forte da extensão: cada conversa corre sozinha, no seu grupo de abas, e você alterna entre elas sem parar nada.

Criar uma conversa

Clique em + (Nova conversa). O botão funciona mesmo com a conversa atual executando — ele só fica bloqueado durante a própria criação, para não criar duas conversas com um clique duplo.

A conversa nova nasce vazia, com o modelo (e o agente) selecionados, e já fica em foco no painel.

Trocar de conversa

Use o seletor “Sessões do OpenCode”. Cada item mostra o nome da conversa e um sufixo:

  • “ · executando” — aquela conversa está rodando;
  • “ · nova resposta” — chegou algo novo enquanto você estava em outra.

Escolher a conversa limpa o aviso de novidade.

Seguir o grupo de abas em foco

Com “Mostrar no painel a conversa do grupo de abas que está em foco” ligado (padrão), basta clicar em uma aba de um grupo: o painel troca para a conversa daquele grupo. A troca tem uma pequena espera (150 ms) para não piscar quando você passa por várias abas.

Criar ou selecionar uma conversa manualmente cancela essa troca automática — o painel não vai “voltar sozinho” para outra conversa logo depois do seu clique.

Criar o grupo junto com a conversa (opcional)

Ligando “Criar um grupo de abas ao iniciar uma nova conversa”, o + já abre uma aba em branco (em segundo plano, na janela do painel) e o grupo com o nome da conversa. É útil quando você quer ver a “âncora” de cada conversa na barra de abas desde o começo; o custo é uma aba em branco por conversa.

Desligado (padrão), o grupo nasce no primeiro uso do navegador ou no anexo de uma aba.

Excluir uma conversa

Use a lixeira (Excluir sessão). A confirmação diz: “Excluir esta sessão? O histórico será removido do OpenCode.”

Ao excluir:

  • o histórico sai do OpenCode;
  • o grupo é liberado: as abas em branco são fechadas e as páginas reais são apenas desagrupadas (nada seu é fechado);
  • se era a conversa exibida, a mais recente passa a ser mostrada.

Limites

  • O painel mantém estado detalhado de até 4 conversas. As demais continuam existindo no OpenCode e recarregam quando você as abre.
  • O vínculo conversa↔grupo fica na sessão do navegador: fechar o Chrome completamente desfaz o vínculo (as abas continuam lá, sem dono).
  • O painel é uma visão só: duas janelas abertas mostram a mesma conversa.

10. Permissões

Modos

Em Configurações → Permissões:

ModoComportamento
Perguntar a cada sitePede na primeira ação em cada domínio
Permitir ações automaticamente (recomendado) (padrão)Não pergunta; respeita a lista de bloqueio
Bloquear açõesSó leitura; nenhuma interação é executada

O que nunca pede permissão

Leitura e coisas de bastidor: listar abas, abrir aba, ler a página, buscar elemento, extrair texto, ler console, ler rede, redimensionar janela e gravar quadros do GIF. Também não pedem: iniciar e parar a gravação de GIF.

O card de permissão

Quando uma ação precisa de aprovação, o card aparece sobre o painel e mostra:

  • o host em destaque, com um ponto de alerta;
  • o que será feito (“Navegar de a.com para b.com”, “Clicar na página”, “Preencher campo ref_3”, “Executar JavaScript na página”…);
  • detalhes: título da aba, URL de destino, valor que será digitado (até 2.000 caracteres), nomes dos arquivos;
  • uma prévia (screenshot) quando existir;
  • o nome da conversa, se o pedido for de outra conversa (“Sessão: …”).

As opções:

BotãoEfeito
Permitir uma vez (Enter)Só esta ação
Permitir nesta sessãoLibera o host enquanto essa conversa existir (guardado só em memória)
Permitir sempre para exemplo.comGrava o host na lista de permitidos
Negar (Esc)Recusa a ação

Pedidos de navegação entre domínios e de plano têm botões próprios: Permitir / Permitir sempre para … / Recusar e Aprovar plano / Recusar.

O rodapé do card lembra: “Você pode revogar permissões em Configurações. O agente nunca deve comprar, criar contas ou burlar captchas sem sua confirmação.”

Tempo para responder

O padrão é 60 segundos. Se você não responder, a ação é negada. O tempo pode ser mudado em Configurações (30 s, 1 min, 2 min, 5 min).

Com o painel fechado

O pedido vira notificação do sistema (“OpenCode Browser: aprovação pendente”) e toca um aviso sonoro. Clicar na notificação abre o painel já com o pedido na tela.

Várias conversas pedindo ao mesmo tempo

Os pedidos entram numa fila: o da conversa que você está vendo aparece primeiro; ao responder, o próximo entra — com o nome da conversa de origem. Nada é perdido nem expira escondido, e ao reabrir o painel todos os pendentes reaparecem.

Enquanto um card está aberto ele cobre o painel, inclusive se for de outra conversa. Para liberar rápido, use Esc (nega) ou responda.

Listas de permitidos e bloqueados

Em Configurações → Permissões:

  • Sites sempre permitidos (um por linha)
  • Sites sempre bloqueados (um por linha)

O bloqueio é avaliado antes de tudo: se o host está na lista de bloqueados, nem o modo “permitir automaticamente” libera.

O formato é só o host, minúsculo, exatamente como aparece na barra de endereços — sem https://, sem caminho, sem porta e sem curinga:

EntradaFunciona?Por quê
github.comSimÉ o host
docs.github.comSimSubdomínio é outro host (precisa de linha própria)
localhostSimHost sem porta
https://github.comNãoO esquema não faz parte do host
github.com/repoNãoCaminho não faz parte do host
*.github.comNãoNão existe curinga
GitHub.comNãoA comparação diferencia maiúsculas

Cada linha é comparada por igualdade. Digitar https://… não dá erro na tela, mas não tem efeito — vale a pena conferir depois de salvar.

11. Quando o agente faz uma pergunta

Além de permissões, o agente pode pedir uma resposta sua — uma escolha, um número, um sim/não. Isso aparece como um card no chat, com o título da pergunta e o status “aguardando”.

Os campos possíveis são: texto livre, número, sim/não, escolha única, múltipla escolha (com a opção “Outra resposta”) e link externo. Campos obrigatórios precisam ser preenchidos para liberar o botão.

  • Responder — envia sua resposta e o agente continua;
  • Cancelar — encerra a pergunta sem resposta (sem confirmação).

Com o painel fechado, chega uma notificação: “O agente precisa de uma resposta: …”.

15. Limites e privacidade

  • Tudo local: a extensão fala com 127.0.0.1; o plugin escuta apenas em loopback (portas 8799–8802) e exige um “hello” da extensão antes de atender.
  • O painel é uma visão só: duas janelas abertas mostram a mesma conversa.
  • Vínculo conversa↔grupo não sobrevive a fechar o Chrome por completo.
  • Até 4 conversas com estado detalhado em memória ao mesmo tempo.
  • Uma resposta em streaming por vez, mas várias conversas podem executar em paralelo.
  • Grupo automático cria uma aba em branco por conversa; grupos de conversas apagadas fora da extensão só são liberados no próximo início do navegador.
  • O card de permissão é modal: enquanto houver um pedido aberto, o painel fica coberto — responda (ou use Esc) para continuar.
